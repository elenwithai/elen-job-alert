# 채용공고 모니터

등록해둔 채용 페이지를 GitHub Actions가 주기적으로 훑고, 새로 올라온 공고만
Claude API가 프로필과 대조해 걸러서 휴대폰으로 보여줍니다.

---

## 1. 배포 순서 (처음 한 번만)

### 1-1. 리포지토리 만들기

1. GitHub에서 **New repository** → 이름 `elen-job-alert`
2. **Public** 선택 (GitHub Pages 무료 사용 조건)
3. README 추가 체크는 **해제** → **Create repository**

### 1-2. 파일 올리기

1. 받은 zip을 컴퓨터에서 압축 해제
2. 리포지토리 화면의 **uploading an existing file** 클릭
3. 압축 푼 폴더 **안의 내용물 전체**를 드래그해서 올립니다
   (`elen-job-alert` 폴더 자체가 아니라 그 안의 `index.html`, `scripts`, `config` … 를 올립니다)
4. 아래 **Commit changes** 클릭

> ⚠️ `.github` 폴더는 이름이 점으로 시작해서 드래그 업로드 때 빠지는 경우가 많습니다.
> 아래 1-3에서 직접 만들어야 합니다. 다른 폴더는 드래그로 잘 올라갑니다.

### 1-3. 워크플로 파일 직접 만들기

1. 리포지토리 화면 → **Add file** → **Create new file**
2. 파일 이름 칸에 정확히 아래를 입력 (`/`를 치면 폴더가 자동으로 만들어집니다)
   ```
   .github/workflows/monitor.yml
   ```
3. 압축 푼 폴더의 `workflow-monitor-yml.txt` 내용을 통째로 복사해 붙여넣기
4. **Commit changes**

### 1-4. Actions에 쓰기 권한 주기

Actions가 수집 결과를 리포지토리에 커밋해야 화면이 갱신됩니다.

**Settings** → 왼쪽 **Actions** → **General** → 맨 아래 **Workflow permissions**
→ **Read and write permissions** 선택 → **Save**

### 1-5. API 키 등록 (ANTHROPIC_API_KEY)

> **키 없이 크롤링만 먼저 시험해보고 싶다면 이 단계를 건너뛰어도 됩니다.**
> 키가 없으면 수집까지만 하고 AI 판단을 건너뜁니다. 수집된 공고는 화면의
> **AI 판단 전** 섹션에 그대로 보입니다. 상세 본문도 함께 받아 보관해두므로,
> 나중에 키를 등록하고 다시 실행하면 **그 본문으로** 판단합니다
> (제목만으로 판단하지 않습니다). 자세한 내용은 아래 2-1 참고.


**키 발급** — https://console.anthropic.com 접속 → 로그인 →
**Settings** → **API keys** → **Create Key** → 이름 아무거나 → 생성된 키 복사
(`sk-ant-` 로 시작. 이 화면을 벗어나면 다시 볼 수 없으니 바로 복사하세요.)

> console.anthropic.com은 claude.ai 구독과 **별도 결제**입니다.
> Billing에서 최소 금액을 충전해야 API 호출이 됩니다.

**GitHub에 등록** — 리포지토리 **Settings** → 왼쪽 **Secrets and variables** →
**Actions** → **New repository secret**

| 칸 | 입력값 |
|---|---|
| Name | `ANTHROPIC_API_KEY` |
| Secret | 복사한 키 붙여넣기 |

**Add secret** 클릭. 이름의 대소문자와 밑줄이 정확해야 합니다.

### 1-6. GitHub Pages 켜기

**Settings** → 왼쪽 **Pages** → Source: **Deploy from a branch** →
Branch: **main** / **/ (root)** → **Save**

1~2분 뒤 같은 화면에 주소가 뜹니다:
```
https://elenwithai.github.io/elen-job-alert/
```

### 1-7. 첫 실행

**Actions** 탭 → 왼쪽 **채용공고 모니터링** → 오른쪽 **Run workflow** → **Run workflow**

초록 체크가 뜨면 성공입니다. 실행 결과 화면을 열면 **어느 사이트에서 몇 건을
가져왔는지 표**가 나옵니다. 이 표가 이후 설정을 고치는 기준입니다.

### 1-8. 휴대폰에서 확인

주소를 폰 브라우저로 엽니다.
- 화면 확인만 먼저 하고 싶으면 주소 끝에 `?demo=1`을 붙이세요. 샘플 공고 5건이
  표시됩니다. 실제 데이터에는 영향을 주지 않습니다.
- 홈 화면에 추가하려면: **아이폰** 공유 버튼 → 홈 화면에 추가 /
  **안드로이드** 메뉴 → 홈 화면에 추가

## 2. 실행 주기와 실행 방식

### 2-1. API 키 없이 수집만 먼저 돌려보기

배포가 제대로 됐는지, 23곳 중 어디가 크롤링되는지를 **비용 0원으로** 먼저
확인할 수 있습니다.

1. **Actions** → **채용공고 모니터링** → **Run workflow**
2. **dry_run** 체크박스를 켭니다 (키를 아직 등록하지 않았다면 켜지 않아도 동일하게 동작합니다)
3. **Run workflow**

결과:

- 목록 페이지 → 개별 공고 링크 추출 → **상세 페이지 방문 → 본문 수집**까지 전부 수행합니다
- AI 호출만 건너뜁니다. Anthropic 요금은 한 푼도 발생하지 않습니다
- 실행 결과 맨 위에 **사이트별 표**가 나옵니다 (어디가 몇 건 잡혔는지)
- 앱 화면에는 **AI 판단 전** 섹션이 생기고, 수집된 공고가 제목·회사·마감일·개별
  상세 링크와 함께 표시됩니다. 카드를 눌러 실제 공고로 이동해보면 크롤링이
  제대로 됐는지 바로 확인됩니다
- 상세 본문은 `data/pending_bodies.json` 에 따로 보관됩니다. 이 파일은 앱이
  내려받지 않으므로 휴대폰 데이터 사용량에는 영향이 없습니다

나중에 **1-5의 API 키를 등록하고 다시 실행**하면, 보관해둔 본문을 그대로 써서
판단합니다. 다시 크롤링하지 않으므로 사이트에 부담도 없고 빠릅니다.

미리 화면을 보고 싶으면 배포 후 주소 끝에 **`?demo=crawl`** 을 붙이면
이 상태의 예시 화면이 뜹니다.

### 2-2. 자동 실행 주기

**하루 1회, 한국시간 오전 8시**에 실행됩니다.
`.github/workflows/monitor.yml`의 `cron: '0 23 * * *'` 가 그 설정입니다
(23:00 UTC = 다음날 08:00 KST).

주기를 늘리려면 시각을 쉼표로 나열하면 됩니다. 예를 들어 하루 2회
오전 8시·오후 8시로 하려면 `'0 23,11 * * *'` 입니다.

> GitHub의 예약 실행은 서버 사정에 따라 5~30분 늦게 시작될 수 있습니다.
> 또 리포지토리에 60일간 아무 활동이 없으면 예약 실행이 자동 중지됩니다.
> 이 앱은 매 실행마다 커밋을 남기므로 보통 문제되지 않습니다.

## 3. 설정 파일 고치는 법

두 파일 모두 GitHub 웹에서 바로 고칠 수 있습니다.
파일 클릭 → 오른쪽 위 **연필 아이콘** → 수정 → **Commit changes**

### 3-1. `config/sources.json` — 모니터링할 페이지

**앱 화면(탭 2)에서 직접 추가·수정·삭제하는 편이 훨씬 편합니다.** 아래는 파일을
직접 고칠 때의 형식입니다. 현재 23곳이 등록돼 있습니다.

개수 제한은 없습니다. `sources` 배열에 항목을 추가하면 됩니다.

```json
{
  "key": "kb_life",
  "company": "KB라이프생명",
  "url": "https://example.com/recruit/list",
  "memo": "경영전략 직무 위주",
  "enabled": true,
  "detail_fetch": true,
  "link_include": ["/recruit/view"],
  "link_exclude": [],
  "max_new_details": 15
}
```

| 항목 | 설명 |
|---|---|
| `key` | 영문 고유 이름. 다른 항목과 겹치면 안 됩니다 |
| `no` | 화면에 표시할 순서 번호 |
| `company` | 화면에 표시될 회사명 |
| `url` | 공고 **목록** 페이지 주소 |
| `memo` | 목록 화면에 함께 보이는 메모 |
| `enabled` | `false`면 수집에서 제외 (지우지 않고 잠시 끌 때) |
| `manual_only` | `true`면 수집·AI 판단에서 빼고 [모니터링 페이지 목록]에만 표시 |
| `detail_fetch` | `false`면 상세 페이지를 안 열고 목록 제목만으로 판단 |
| `render_mode` | `auto`(기본)·`always`·`never`. 아래 4-2 참고 |
| `min_expected_links` | 이 건수보다 적게 잡히면 브라우저 렌더링으로 재시도 |
| `render_wait_selector` | 브라우저 렌더링 시 기다릴 요소 (예: `.job-list li`) |
| `link_include` | 이 조각이 URL에 있으면 공고로 인정. 가장 중요한 설정 |
| `link_exclude` | 이 조각이 있으면 제외 |
| `max_new_details` | 한 번 실행에 새로 열어볼 상세 페이지 최대 수 (현재 6) |

**`link_include`를 정하는 법**: 해당 사이트에서 공고 하나를 열고 주소창을 봅니다.
예를 들어 주소가 `https://careers.ey.com/ey/job/1234567/` 이면 공고 주소에는
`/ey/job/` 이 공통으로 들어가므로 `["/ey/job/"]` 을 넣습니다.

마지막 항목 뒤에 쉼표를 남기면 JSON 오류가 납니다. Actions가 빨간 X로 표시됩니다.

### 3-2. `config/profile.json` — 내 프로필과 판단 기준

`profile_text`에 경력과 희망 직무를 자유롭게 쓰면 그대로 AI에게 전달됩니다.
`judging_rules`는 yes/no를 가르는 기준입니다.

- 추천이 **너무 많이** 뜨면 → `judging_rules`의 no 조건을 늘립니다
  (예: `"직무명에 '매니저' 이상 직급이 없으면 no"`)
- 추천이 **너무 적게** 뜨면 → yes 조건을 넓힙니다

줄바꿈은 배열의 한 줄씩으로 나눠 쓰면 됩니다. 고친 뒤 Actions를 수동 실행하면
바로 반영됩니다. 단, **이미 판단이 끝난 공고는 다시 판단하지 않습니다.**
전부 다시 판단하려면 `data/jobs.json`을 지우고 다시 실행하세요.

## 4. 크롤링이 어떻게 도는지

목록 페이지 제목만 보고 판단하지 않습니다. 2단계로 돕니다.

```
1단계  목록 페이지 접속 → 개별 공고 상세 링크를 전부 추출
2단계  그중 '처음 보는 공고'만 상세 페이지에 직접 접속 → 본문 수집
3단계  본문 + 프로필을 Claude에게 전달 → 적합 여부 판단
```

### 4-1. 2단계 크롤링

공고 카드의 링크는 **항상 그 공고만의 상세 페이지 주소**입니다. 회사 목록 페이지
주소가 공고로 저장되지 않도록 세 겹으로 막아둡니다: 목록 페이지 자기 링크 제외,
페이지네이션(`?page=2` 등) 제외, 그리고 저장 직전 최종 확인. 만약 그래도 목록
주소가 걸리면 카드에 빨간 `⚠ 목록 페이지 링크` 표시가 붙어 바로 눈에 띕니다.


이미 본 공고는 상세 페이지를 다시 열지 않습니다. 공고 주소로 고유 ID를 만들어
`data/jobs.json`에 기록해두기 때문입니다. 그래서 매일 도는 요청 수는
"목록 페이지 수 + 그날의 신규 공고 수"만큼입니다.

상세 페이지 접근이 막히거나 본문이 비면 그 공고는 **목록 정보만으로 판단**하고,
카드에 `목록 정보만으로 판단` 표시가 붙습니다. AI에게도 "본문이 없으니 확신을
낮게 잡으라"고 전달합니다.

AI 호출이 실패하면 그 공고는 **판단 보류** 섹션에 남고 다음 실행 때 자동으로
다시 시도합니다. 한 건이 실패해도 나머지 수집은 멈추지 않습니다.

### 4-2. 자바스크립트로 목록을 그리는 사이트 (삼성·한화 등)

국내 대기업 채용포털은 HTML에 공고가 없고 접속 후 자바스크립트가 목록을
그려 넣는 경우가 많습니다. 이런 사이트는 일반 요청으로는 링크가 0건입니다.
그래서 **처음부터 2단 구조**로 만들어 뒀습니다.

```
1차   일반 요청(requests)으로 HTML을 받아 링크 추출        ← 빠르고 가벼움
      ↓ 링크가 min_expected_links 보다 적으면
2차   헤드리스 크로미움으로 페이지를 실제 렌더링 후 재추출  ← 자동 폴백
      ↓ 그래도 0건이거나 로그인이 필요하면
3차   manual_only: true 로 전환 → 수동 확인 전용
```

2차까지 성공하면 그 사이트는 **상세 페이지도 브라우저로** 가져옵니다.
수집 상태 화면에 `브라우저 폴백` 표시가 붙어서 어떤 사이트가 어느 방식으로
수집됐는지 바로 보입니다. 브라우저 렌더링은 느리므로(사이트당 5~15초)
가능한 곳은 계속 일반 요청을 씁니다.

`render_mode`로 강제할 수도 있습니다.

| 값 | 동작 |
|---|---|
| `auto` (기본) | 일반 요청 먼저, 부족하면 브라우저로 재시도 |
| `always` | 처음부터 브라우저 렌더링 (JS 사이트로 확정된 경우) |
| `never` | 일반 요청만 (브라우저 폴백 비용이 아까울 때) |

**3차, 수동 확인 전용으로 돌리기** — 브라우저로도 안 잡히거나 로그인이
필요한 사이트는 `sources.json`에서 그 항목만 이렇게 바꾸세요.

```json
"manual_only": true
```

그러면 그 회사는 수집·AI 판단 대상에서 빠지고, 앱의 **모니터링 페이지 목록**에
`수동 확인 전용` 표시와 함께 남아 손으로 눌러 확인할 수 있게 됩니다.
Actions 실행 시간도 그만큼 줄어듭니다.

### 4-3. AI 판단 전 1차 필터

Claude API로 보내기 전에 두 가지를 먼저 걸러냅니다. 걸러진 공고는 API 호출을
하지 않으므로 비용이 들지 않고, 앱의 **AI가 제외한 공고**에 `자동 제외` 표시와
함께 남습니다.

**① 채용공고가 아닌 게시물** — 채용 게시판에는 인사발령, 조직도, 지배구조·가치체계
소개, 공지사항 같은 글이 섞여 올라옵니다. 제목에 그런 단어가 있고 "채용/모집"
신호가 없거나, 본문에 담당업무·자격요건·접수기간이 하나도 없으면 제외합니다.

**② 지원 대상이 아닌 고용형태** — 계약직, 신입, 인턴, 파트타이머, 설계사 모집 등.
단 제목에 "경력"이나 "정규직"이 함께 있으면 남깁니다
(예: "신입/경력 채용", "계약직 후 정규직 전환"은 통과).

기준은 `config/profile.json`의 `auto_exclude`에서 직접 고칠 수 있습니다.

```json
"auto_exclude": {
  "employment_types": ["계약직", "신입", "인턴", ...],
  "keep_if_contains": ["경력", "정규직", ...],
  "non_job_posts": ["인사발령", "조직도", "가치체계", ...]
}
```

너무 많이 걸러지면 `employment_types`에서 단어를 빼고, 쓸데없는 글이 계속 올라오면
`non_job_posts`에 단어를 추가하세요.

### 4-4. 마감된 공고 처리

AI 판단 **전에** 마감 여부를 먼저 확인합니다. 이미 마감된 공고는 Claude API로
보내지 않으므로 그만큼 비용이 들지 않습니다.

마감 판정 기준은 두 가지입니다.

| 상황 | 판정 |
|---|---|
| 상세 본문에서 마감일을 읽은 경우 | 그 날짜가 지나면 마감 |
| 본문에 "접수마감", "종료되었습니다" 등의 문구가 있는 경우 | 날짜와 무관하게 마감 |
| 마감일을 못 읽었거나 "상시 채용"인 경우 | 발견일로부터 **30일** 경과 시 마감 |

마감일 파싱은 `scripts/deadline.py`가 담당하며 아래 표기를 인식합니다.

| 표기 | 예 |
|---|---|
| 기간 범위 (**끝 날짜**를 씀) | `접수기간 2026.08.19 ~ 2026.09.01` |
| 두 자리 연도 | `24.10.10(목) ~ 24.10.20(일)` / `'20.4.6 ~ '20.4.13` |
| 끝 날짜에 연도 없음 | `2025년 10월 13일 ~ 10월 22일` |
| 요일·시각 포함 | `2026.09.01(화) 18:00까지` |
| 연도 없는 월/일 | `8월 19일 ~ 9월 1일` |
| 제목 축약 | `2026 하반기 채용 (~10/20)` |
| 상시 | `상시채용`, `채용시 마감`, `수시채용` |
| 마감 상태 문구 | `(접수마감)`, `모집이 종료되었습니다` |

특정 사이트만 다른 형식을 쓴다면 `sources.json`의 해당 항목에
`deadline_patterns`로 정규식을 넣으면 기본 파서보다 먼저 적용됩니다.

```json
"deadline_patterns": ["마감\\s*:?\\s*(20\\d{2}[.\\-/]\\d{1,2}[.\\-/]\\d{1,2})"]
```

30일 기준은 워크플로의 `STALE_DAYS` 값으로 바꿀 수 있습니다. 마감 처리된 공고는
삭제되지 않고 앱의 **마감된 공고** 섹션에 남으며, 마지막으로 발견된 지 45일이
지나면 그때 정리됩니다.

날짜 계산은 앱과 서버 모두 **한국시간 달력 날짜** 기준입니다. 휴대폰 시간대가
달라도 같은 결과가 나옵니다.

### 4-4. 호출 상한

한 번 실행의 AI 호출 상한은 40건이고, 사이트당 상세 페이지 방문은 6건입니다.
넘치는 신규 공고는 **판단하지 않고 다음 실행으로 넘깁니다** — 본문 없이 제목만으로
AI에 넘기지 않기 위해서입니다.

등록 사이트가 23곳이라 첫 실행에서는 신규 공고가 많이 밀립니다. 초반 며칠은
Actions에서 수동 실행을 두어 번 더 돌리면 빨리 채워집니다. 한 번에 더 처리하려면
`sources.json`의 `max_new_details`와 워크플로의 `MAX_AI_CALLS`를 올리세요.

## 5. 화면 사용법

화면은 하단 탭 두 개로 나뉩니다.

### 탭 1 — AI 추천 공고

- **AI 추천 공고** — 적합 판정(yes)을 받은 공고. 기본은 안 본 것만 보입니다.
  공고 제목을 누르면 새 탭으로 원문이 열리고 **그 즉시 읽음 처리**됩니다.
  읽는 중에 카드가 사라지면 곤란하니, 흐려지기만 하고 목록에서는 다음
  새로고침 때 빠집니다.
- **전체** 토글 — 이미 읽은 공고까지 포함해서 봅니다.
- **숨기기** — 관심 없는 공고를 "안 본 공고" 목록에서만 뺍니다. **전체**에서는 계속 보입니다.
- **카드 우측 상단 X** — 그 공고를 **완전히** 삭제합니다. 전체 보기에서도 사라지고,
  다음 날 같은 공고가 다시 수집돼도 나타나지 않습니다. 누르면 확인창이 한 번 뜹니다.
  실수로 지웠다면 바로 뜨는 `실행취소` 또는 맨 아래 **삭제한 공고 · 모두 복구**로 되돌립니다.
- **D-배지** — 카드 오른쪽 위에 마감까지 남은 일수가 표시됩니다.
  D-3 이하와 D-DAY는 빨간색, D-7 이하는 주황색입니다. 목록은 **마감 임박순**으로
  정렬되고, 같으면 최근 발견 순입니다. 마감일이 없는 공고는 맨 뒤로 갑니다.
- **마감된 공고** — 접힌 섹션. 마감일이 지났거나, 마감일을 못 읽은 채 발견 후
  30일이 지난 공고가 여기로 내려갑니다. 삭제되지 않고 남으니 나중에 참고할 수 있습니다.
- **AI 판단 전** — 수집은 끝났지만 아직 판단하지 않은 공고입니다. API 키가 없거나
  dry_run 으로 돌렸을 때, 또는 AI 호출 한도를 넘겼을 때 여기에 모입니다.
  `본문 수집 완료` 표시가 있으면 상세 본문까지 받아둔 상태라, 키를 넣고 다시
  실행하면 그 본문으로 판단합니다.
- **판단 보류** — AI 호출이 실패한 공고. 다음 실행에서 자동 재시도됩니다.
- **AI가 제외한 공고** — AI가 no로 판단한 것들. 접혀 있습니다.
  여기 좋은 공고가 자꾸 들어가면 `judging_rules`를 손볼 신호입니다.
### 탭 2 — 모니터링 페이지

- **회사명을 한 번 누르면** 그 채용 페이지로 바로 이동합니다(새 탭). 읽음 처리와 무관합니다.
- **No.** — 목록 순서. 항목을 추가·삭제하면 1번부터 자동으로 다시 매겨집니다.
- **연필 아이콘** — 회사명·주소·메모·공고 링크 조각을 그 자리에서 수정합니다.
- **X 아이콘** — 바로 삭제됩니다. 아래에 `실행취소` 버튼이 5초간 뜨므로 잘못 눌러도 되돌릴 수 있습니다.
- **+ 추가** — 새 채용 페이지를 등록합니다.
- **수집 상태 확인** — 사이트별로 몇 건을 가져왔는지. 링크 0건이면 설정을 봐야 합니다.

### 화면에서 고친 내용을 자동 수집에 반영하기 (중요)

GitHub Actions는 서버에서 돌기 때문에 **휴대폰에 저장된 편집 내용을 볼 수 없습니다.**
화면에서 추가·수정·삭제하면 주황색 배너가 뜨고 탭에 점이 붙습니다. 반영 절차는
두 단계입니다.

1. **[sources.json 복사]** — 완성된 파일 내용이 통째로 복사됩니다.
   자동 복사가 막히면 아래에 텍스트 상자가 열리니 길게 눌러 복사하세요.
2. **[GitHub에서 붙여넣기 ↗]** — `config/sources.json` 편집 화면이 바로 열립니다.
   기존 내용을 **전체 선택해서 지우고** 붙여넣은 뒤 **Commit changes**.

`link_include`, `render_mode` 같은 튜닝값은 복사본에 그대로 보존되므로 덮어써도
설정이 사라지지 않습니다. 되돌리려면 **[변경 되돌리기]** 를 누르면 파일 상태로 복귀합니다.

> GitHub 토큰을 앱에 저장해 자동 커밋하는 방식은 쓰지 않았습니다. 그 토큰은
> 리포지토리 전체 쓰기 권한을 갖고 휴대폰에 계속 남기 때문에, 가끔 하는 설정
> 변경을 위해 상시 위험을 지는 편이 손해라고 판단했습니다.

읽음·숨김·삭제 기록과 화면 편집 내용은 그 휴대폰의 브라우저에만 저장됩니다.
기기를 바꾸거나 브라우저 데이터를 지우면 초기화됩니다.

## 7. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 화면이 "데이터를 불러오지 못했습니다" | Actions를 아직 한 번도 안 돌렸을 때 정상입니다. Actions 탭에서 수동 실행 |
| Actions 빨간 X | 로그 확인. `Permission denied` → 1-4의 쓰기 권한 / JSON 오류 → 설정 파일 쉼표 |
| 특정 사이트 링크 0건 | 브라우저 폴백까지 실패한 경우입니다. 아래 진단 절차 참고 |
| Actions가 오래 걸림 | 브라우저 폴백이 도는 사이트가 많을 때입니다. 안 되는 곳은 `manual_only: true`로 |
| `playwright install` 실패 | 러너 일시 오류. 재실행하면 대개 해결됩니다. 실패해도 일반 요청 수집은 계속됩니다 |
| 전부 "AI 판단 전" | API 키가 없는 상태입니다. 수집은 정상이며, 1-5로 키를 등록하고 다시 실행하세요 |
| 전부 "판단 보류" | 키는 있으나 인증 실패(오타) 또는 console.anthropic.com 잔액 부족 |
| 공고가 갑자기 줄었다 | 마감 처리됐을 수 있습니다. **마감된 공고** 섹션을 열어보세요 |
| 지운 공고가 다시 안 보임 | 정상입니다. 맨 아래 **삭제한 공고 · 모두 복구**로 되돌립니다 |
| 무관한 글이 계속 뜬다 | API 키를 등록해야 AI 판단이 켜집니다. 그 전에는 1차 필터만 동작합니다 |
| 원하는 공고가 자동 제외됐다 | `profile.json`의 `auto_exclude`에서 해당 단어를 빼세요 |
| 추천이 0건 | 정상일 수 있습니다. "AI가 제외한 공고"를 열어 판단이 타당한지 보세요 |
| X를 눌러도 삭제 안 됨 | 해결된 문제입니다. 그래도 그러면 캐시 문제이니 아래 항목 참고 |
| 화면이 옛날 그대로 | PWA 캐시입니다. 새로고침 버튼(↻) → 그래도 그러면 홈 화면 앱을 지웠다 다시 추가 |

### 첫 실행 후 튜닝 절차 (중요)

초기 URL과 `link_include` 패턴은 실제 접속 확인을 거치지 않은 **추정값**입니다.
아래 순서대로 한 번만 돌리면 어디를 고쳐야 하는지 바로 나옵니다.

**1단계 — 그냥 한 번 돌려서 표 확인**

1. 리포지토리 **Actions** 탭
2. 왼쪽 목록에서 **채용공고 모니터링** 클릭
3. 오른쪽 **Run workflow** 버튼 → 옵션은 건드리지 말고 **Run workflow**
4. 1~3분 뒤 실행 항목을 클릭하면 맨 위에 **표**가 있습니다

| 사이트 | 목록 | 링크 | 신규 | 상세 성공 | 상세 실패 | 비고 |
|---|---|---|---|---|---|---|

- **링크가 1 이상** → 그 사이트는 정상입니다
- **링크 0** → 2단계로
- 비고에 `브라우저 폴백`이 보이면 자동 폴백이 작동한 것입니다 (정상)

**2단계 — diagnose 모드로 한 번 더**

1. 다시 **Actions → 채용공고 모니터링 → Run workflow**
2. 이번에는 **diagnose** 체크박스를 **켭니다**
3. 함께 **dry_run**도 켜면 AI 호출이 없어 비용이 0원입니다
4. **Run workflow**

이러면 링크를 못 찾은 사이트의 실제 HTML 앞부분이 `data/crawl_report.json`에
저장됩니다.

**3단계 — 결과 보내주기**

아래 둘 중 편한 방법으로 주시면 `link_include` 패턴을 같이 맞추겠습니다.

- 리포지토리에서 `data/` → `crawl_report.json` 클릭 → 오른쪽 **Raw** →
  전체 복사해서 붙여넣기 (또는 **Download**로 받은 파일 첨부)
- Actions 실행 결과의 **표 부분 스크린샷**

함께 알려주시면 훨씬 빨라지는 것: 안 잡힌 회사의 **공고 하나를 실제로 연
주소**. 예를 들어 `https://careers.ey.com/ey/job/1234567/` 처럼 주소 하나만
있으면 패턴을 정확히 잡을 수 있습니다.

**4단계 — 반영**

고친 `sources.json`을 커밋한 뒤 **dry_run**으로 한 번 더 돌려 링크가 잡히는지
확인하고, 잡히면 옵션 없이 정식 실행하면 됩니다.

### Run workflow 옵션 정리

| 옵션 | 용도 |
|---|---|
| (둘 다 끔) | 정상 실행. AI 판단까지 수행 (키가 없으면 자동으로 수집 전용) |
| **dry_run** | 수집만. AI 호출 없음 = 비용 0원. 키 없이도 동작 |
| **diagnose** | 링크 0건 사이트의 HTML 앞부분을 리포트에 저장 |

## 8. 사이트가 안 잡힐 때 URL 바꾸는 법

`sources.json`의 초기 URL은 **추정값**입니다. 실제로 접속해본 적이 없어서
그대로 동작한다고 장담할 수 없습니다. 첫 실행 결과 표를 보고 고치면 됩니다.

1. 폰이나 PC에서 그 회사 채용 페이지를 엽니다
2. 공고 **목록**이 실제로 보이는 화면의 주소를 복사 → `url`에 넣습니다
3. 공고 하나를 열어 주소의 공통 조각을 찾습니다 → `link_include`에 넣습니다
4. Actions에서 **dry_run**으로 돌려 링크가 잡히는지 확인합니다

**그래도 0건이면** 그 사이트는 자바스크립트로 목록을 그리는 방식이라
지금 방식(HTML 직접 읽기)으로는 잡히지 않습니다. 이 경우 선택지는:

- 그 회사만 `enabled: false`로 끄고 **모니터링 페이지 목록**에서 직접 눌러 확인
- 채용 사이트가 제공하는 RSS나 검색 API 주소를 찾으면 알려주세요. 그 주소로
  바꾸면 대개 해결됩니다
- 링크드인 등 다른 경로의 같은 회사 공고 페이지를 `url`로 넣기

## 10. 화면이 이상할 때 — 자가진단

주소 끝에 **`?debug=1`** 을 붙이면 화면 위에 진단 패널이 뜹니다.

```
https://elenwithai.github.io/elen-job-alert/?debug=1
```

여기서 확인할 수 있는 것:

- `가로 초과` — 0px 이 아니면 가로 스크롤이 생긴 상태입니다
- `초과 요소` — 화면 밖으로 삐져나간 요소의 태그·클래스명
- `화면 폭 · DPR` — 이 휴대폰의 실제 CSS 폭
- `목록URL이 걸린 카드` — 0건이어야 정상입니다
- `카드 링크` — 각 공고 카드가 실제로 어디로 연결되는지

실기기에서 문제가 보이면 이 패널을 캡처해서 보내주시면 원인을 바로 짚을 수 있습니다.
`?debug=1` 을 빼면 다시 사라지므로 평소 사용에는 영향이 없습니다.

화면만 확인하고 싶을 때는 **`?demo=1`** 을 붙이면 샘플 공고로 표시됩니다.
